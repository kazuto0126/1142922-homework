## 2. 目標 / 不做的事 / 失敗條件

**目標**
1. 電腦（後手）在任何情況下都不會輸，而且有窮舉驗證可以證明。
2. 九格 × 兩陣營，每一手都有對應的主角技能演出。
3. 3D 棋盤可以拖曳旋轉、縮放；放技能時鏡頭會自動運鏡。
4. 三種結局（勝 / 和 / 敗）各有自己的音樂和演出。
5. 放在 GitHub Pages，打開網址就能玩，不用安裝任何東西。

**不做的事**
- 角色 3D 模型（拿不到能合法、輕鬆取得的模型）→ 角色一律用 2D 立繪。
- 角色語音、TTS 語音 → 台詞用字幕呈現。
- 線上連線對戰、帳號系統。
- 「簡單難度」或會故意讓玩家贏的模式 → 會讓「電腦不敗」變得模糊。
- 提示功能、AI 勝率熱度圖。

**失敗條件**（就算能跑也算失敗）
- 電腦輸了任何一局。
- 演出太長又不能跳過，玩兩局就膩。
- 老師的電腦打不開或卡頓（例如外部 CDN 掛掉、檔案太大）。
- 網頁標題沒有「1142922」和「HW06」。
- 音樂蓋過特效音（使用者的長期偏好：**音效一定要比音樂大聲**）。

1. **標題畫面**：遊戲名稱、兩位領袖對峙的畫面，加上「開始」按鈕（瀏覽器規定要先點一下才能播音樂）。

### 5.7 3D 場景與操作 【我的提議】

## 6. 演算法（已完成，待移植成 JS）

- 完整 Minimax（Negamax 形式）+ 記憶化，盤面全部算完，所以電腦每一步都是數學上最佳的一步。
- 評分會讓 AI 贏的時候用最快的步數贏。
- 選步順序：分數最高（保證不輸）→ 陷阱最多 → 隨機（讓每局有變化）。
- C# 版已在 `D:\mid\TicTacToe-1142922` 窮舉驗證：489 局 X 贏 0 局；6,112 條同分路線全部不輸；能一步獲勝時一定直接贏；對照組的笨 AI 輸 429 局，證明驗證程式確實抓得到輸棋。
- JS 版 `ai.js` 不碰畫面，可以單獨用 Node 跑同一套窮舉驗證（`tests/verify-ai.mjs`）。

演出的「關鍵一手」判斷也用同一個 AI 模組：擋下對方必勝的一格 = 對手原本一步就能連線的格子；雙殺 = 下完之後自己有兩條「再一步就連線」的線。

```
    ai.js             不敗演算法（純邏輯，Node 也能跑）
    game.js           狀態機：標題 → 選模式 → 選陣營 → 對局 → 結局
    scene.js          Three.js 場景、棋盤、鏡頭、點擊判定
    fx/               每格一個技能特效檔 + 兩陣營入場、合體技、結局
    cutin.js          2D cut-in 疊層（立繪 + 招式名稱 + 台詞字幕）
    audio.js          Web Audio：音效、音樂、音量優先順序
    assets.js         素材清單；缺素材時自動產生替代圖
  vendor/three/       Three.js（固定版本，含 OrbitControls）
  assets/img/         領袖 2 張、主角 9 張立繪、9 張世界背景
  assets/music/       9 首世界主題曲（去人聲、只取片段）+ 預留兩位領袖的位置
  assets/sfx/         音效
  tests/verify-ai.mjs 窮舉驗證
  docs/設計文件.md    本文件
```

- **素材替代圖**：每張圖都有程式產生的替代版本（陣營色剪影 + 角色名稱），所以就算素材還沒到位，遊戲也能完整玩、所有演出照常跑。素材到位後只要放進資料夾、改素材清單就好。
- Three.js 用一個固定版本（r16x 系列），從 npm 官方套件取出需要的檔案放進 `vendor/`。下載前會先跟你確認檔名、來源和大小。

## 8. 效能

- 目標：一般筆電的內建顯示卡也能維持 60 fps。
- 解析度倍率上限 2，粒子數量有上限；同時只跑一個大型特效。
- 設定中有「畫質：高 / 低」。低畫質會減少粒子、關閉後製發光效果。
- 瀏覽器不支援 WebGL 時，顯示提示訊息。
- 整站目標小於 25 MB，主要是音樂和圖片；音樂用 mp3 約 112–128 kbps。
